yaw or banking: both wings should remain visible with only mild foreshortening
and a small height difference. Inspect the actual back attachment in a wearing preview;
an oblique prompt alone is not evidence that the output meets this requirement.

## Local preview

Requires the existing PixelHeroes assets, Node dependencies and Python with Pillow.

```sh
npm run capes:preview
```

Open http://localhost:5317/tools/cape-preview.html.
The expandable appearance panel runs the real chat UI with all owned capes in an
isolated test inventory. Selecting/removing a cape updates the wearing preview.
It does not grant items to or change an existing user's inventory.

## Integration

`npm run capes:import` creates `assets/pixelheroes/Cape/PixelLab*.png` and registers
all 19 names in the existing `manifest.json`. Run it again after reimporting the
base PixelHeroes assets. Originals here are tracked separately from licensed
third-party assets in the ignored `assets/` directory.

The current atlas is 1024×1120. Its upper portion retains a 32px thumbnail and the
legacy 64px frames as a small fallback. At y=992 it stores one or eight **128px
cells with original-size source pixels**. The body stays at (32,32), preserving
its original position and pixel pitch. Source images are not squeezed into a
64px body cell. Only VectorJet and OrbitalDrones use exact 2:1 reduction and float
above the head. CrimsonDrive is mirrored before attachment.

`tools/cape-layout.json` defines the actual attachment point in source pixels,
its target in body coordinates, and these explicit scale/flip exceptions.
Animated IDs end in `Animated`. The composer
samples the wings at 8fps, repeats idle body poses to retain the original 1.6fps
body cadence, and retains the normal 10fps run and action lengths. Special actions
sample the wing strip per action frame; these accessories do not follow a full
skeletal rig for rolling or falling poses.

Animation source PNGs are stored in each animated accessory's subdirectory.
All eight native frames use the same attachment coordinate, without per-frame
cropping or resizing. The generated GIFs and `*-placed.png` preview only the
accessories. `try-on-native.png` is the latest browser comparison. Earlier
`try-on.png`/`try-on-v2.png` files record the smaller initial iterations.

The desktop renderer adjusts the expanded frame's drawing origin so the body
does not shrink or move. Face avatars use the cached body-only frame so a large
halo/wing cannot displace the face crop. The battle panel uses the matching crop
offset and retains its short idle pause.

## Generation

`tools/pixellab-mcp.mjs` uses the official HTTP MCP endpoint. Supply
`PIXELLAB_TOKEN` through the calling environment; no credentials are saved here.
All originals and animation frames were generated through PixelLab.
